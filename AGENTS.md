# tdlib-multi-mcp — AGENTS.md

Этот файл — обязательное чтение для любого AI-агента (Antigravity, Kilo, Codex, Claude),
работающего с данным проектом.

## Назначение проекта

MCP-сервер (`stdio` JSON-RPC, согласование версии через установленный MCP SDK) для управления несколькими
аккаунтами Telegram через официальную библиотеку **TDLib**.

## Ключевые принципы

### Безопасность
- Пара `api_id`/`api_hash` выбирается только через `config.credentials_for_lang_pack`.
  Используются опубликованные identities официальных приложений по решению владельца.
  Не проси пользователя получать собственную пару и не создавай config.env.
  Не смешивай Android/iOS/macOS/Desktop credentials и `lang_pack`. Не логируй API hash.
- Сессии распаковываются **только** в RAM-диск `/dev/shm/tg_mcp_<uid>/` и очищаются при завершении.
- Прокси проверяются **изолированно** — до добавления к аккаунту.

### Хранение сессий
- TDLib хранит состояние в директории на диске.
- Мы упаковываем эту директорию: `tar+gzip` → `base64` → поле `session_blob TEXT` в SQLite.
- При запуске: Base64 → распаковка → `/dev/shm/tg_mcp_<uid>/<account_id>/`.
- После завершения сессии: директория упаковывается обратно и обновляется в БД.

### Device Fingerprints
- Каждый аккаунт получает уникальный, **неизменяемый** профиль устройства.
- Профиль фиксируется при первом добавлении и хранится в `accounts.db`.

### Прокси
- Сбор из открытых источников (`proxmint`, `monosans`, `proxifly`).
- Изолированный чекер проверяет прокси через `api.ipify.org` **без** активации сессии Telegram.
- При падении прокси — автоматическая замена из пула.

## Команды запуска

```bash
cd ~/.agents/mcp/telegram-mcp
source venv/bin/activate

# Запуск сервера (обычно запускается через mcp-hub)
python server.py

# Тесты
pytest tests/ -v

# Синтаксическая проверка всего кода
python -m py_compile server.py config.py
python -m py_compile core/*.py auth/*.py proxy/*.py db/*.py
```

## Обязательный рабочий цикл для всех агентов

Целевая установленная версия: **Python 3.14.4**, не Python 3.11.

1. До планирования и правок выполни `scripts/rag sync` и
   `scripts/rag query "<задача и затронутая подсистема>"`. Прочитай найденные
   исходники. Если RAG недоступна, сообщи об этом; не выдумывай результат поиска.
2. Прочитай последние указания пользователя. При конфликте с документацией
   выполни актуальное указание и исправь устаревшую документацию.
3. Запиши краткий план на ближайшие 3 шага: изменение, проверка, следующий шаг.
   Перед каждым новым шагом пересмотри план по фактическому результату.
4. После изменения поведения добавь регрессионную проверку, выполни тесты на
   Python 3.14.4 и обнови TODO.md и документацию. Не объявляй mocked тест
   подтверждением настоящего входа в Telegram.
5. После изменения файлов выполни `scripts/rag sync`; новые файлы сначала
   добавь в git index. После коммита повтори sync. Таймер каждые 60 секунд
   страхует изменения tracked файлов, но не заменяет этот рабочий цикл.
6. Прежде чем завершить работу, проверь git diff, исключение секретов и результат
   поиска RAG по изменённой подсистеме. Отчитайся о тестах и оставшихся блокерах.

Установка правил: `scripts/install-agent-rules`. Инструкции не могут гарантировать
послушание любого стороннего агента; таймер независимо обновляет индекс.
